# v0.7.2 发布复核

> patch 发布。基线 `0.7.1`（2026-09-22，发布提交 `ce55cc8`，tag `v0.7.1`）。发布日期 2026-09-22。
> 执行依据：[`docs/release-checklist.md`](release-checklist.md)（本版本是该检查单第一次被完整走一遍）。

## 发布动因

`0.7.1` 之后落地的都是缺陷修复与发布/测试工程收口，没有新增产品能力，因此按 semver 判为 **patch**。
其中一条构成立即发布的硬理由：**账号切换的数据隔离缺陷**（PR #113）。已登录用户登出或切换到另一个
账号时，前一个账号尚未返回的云端进度响应仍会被写入当前账号的本地存储——两个账号的学习记录可能互相
污染。这条缺陷原本早在 PR #83 就修过，因为 head 分支被删导致 PR 被自动关闭而从未合并，是 R14.4 的
工作保全审计把自己扫了出来。修完再等一个「顺手」的发布，等于让隔离缺陷在多账号用户身上继续存活。

## 回滚方案

1. **账号隔离（最高优先）**：revert PR #113 的两个提交即恢复旧行为，但那会把跨账号写入的缺陷放回去，
   因此只有在 `isCurrent` 守卫引发新的误判（例如正常 hydration 被整体丢弃）时才回滚，且范围应收窄到
   具体调用点，而不是撤销守卫本身。
2. **红线文案承载面**：课文页兜底（PR #109）与分享页风险行（PR #116）各自独立成 commit，可单点 revert，
   但会同时让 `check:risk-warning` 的接线门禁或 e2e 红线套件变红——回滚需连门禁一起调整，不能只撤代码。
3. **门禁类改动**（R14.3/R14.4/R14.5/R14.6/R14.8）不改运行时：revert 对应 commit 即恢复原流水线。
4. 无迁移，故无需数据库回滚；`git revert` 后重新部署即完成站点回滚，Vercel 亦可直接把 Production
   Deployment 切回上一版作为止血，随后仍需用 revert 收敛历史。
