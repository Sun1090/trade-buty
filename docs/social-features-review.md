# R13.22 社交功能轻量化设计评审

> 日期：2026-09-12 · 范围：v0.6 是否以及如何加入社交功能
> 结论：先交付「用户主动发起的学习里程碑分享」这一条最小社交链路；v0.6 不引入账号关系链、评论区、排行榜、关注数或可见性设置。

## 1. 评审输入

本项目的市场调研把社区列为长期护城河，同时把 Stock Academy 的班级排行榜列为差异化案例。这个结论只能说明「社交可能有价值」，不能直接推出「应该立刻做排行榜或评论区」：

- BabyPips 的护城河来自多年积累的论坛内容与信任，不是单点排行榜组件。
- Stock Academy 的班级排行榜依赖大规模付费班级、讲师运营和反作弊体系，本项目的定位是免费、匿名优先、无账号也能完成主路径。
- `docs/plan.md` 的内容宪法要求不制造收益暗示和用户间对抗；交易学习天然包含亏损、回撤和风险承受差异，公开比较很容易被误解成能力或收益排名。
- 中文交易教育市场已有大量由交易所、荐股群和财商课运营的“社区”，其中混入营销、喊单和诈骗的风险显著。评论区一旦上线，审核、举报、封禁、未成年人保护和数据保留都会成为不可逆的运营负担。

因此本次评审把“社交”拆成三层，而不是做一个大而全的社区：

| 层级 | 代表功能 | v0.6 决策 | 原因 |
|---|---|---|---|
| 异步表达 | 分享自己的学习里程碑 | ✅ 交付 | 用户主动触发、无账号依赖、无公开身份和进度明细 |
| 公开比较 | 排行榜、连胜榜、收益率榜 | ❌ 暂不引入 | 会改变学习动机，交易场景还可能诱发冒险行为 |
| 双向互动 | 评论、私信、关注、好友 | ❌ 暂不引入 | 审核、反垃圾、隐私和安全成本超出当前团队规模 |

## 2. 已交付的最小实现

### 2.1 里程碑模型

`src/lib/milestone-share.ts` 定义七级里程碑：

1. 读完第 1 课
2. 读完 10 课
3. 完成第 1 个篇章
4. 完成 5 个篇章
5. 连续学习 7 天
6. 读完学习路线一半
7. 读完全部课程

只选当前达成的最高级别，不显示“距离下一级还差 X”来制造持续催促。没有任何进度时组件完全不渲染。

### 2.2 分享行为

`src/components/milestone-share-button.tsx` 遵守以下契约：

- 只有用户点击按钮才会生成分享文案或打开系统分享面板。
- 支持 Web Share API；用户取消时视为“不作选择”，不复制、不报错、不发送失败事件。
- Web Share 不可用或非取消失败时，降级为复制文案；剪贴板失败才显示可读错误。
- 分享文案只包含已读数量、总数量、完成篇章数和连续天数等聚合值。
- 分享链接固定为 `/{locale}/path`，不携带进度、身份、邀请码或任何查询参数。
- 主按钮使用原生 `<button>`，最小高度 40px；复制结果通过 `aria-live="polite"` 播报，错误使用 `role="alert"`。

### 2.3 隐私与数据边界

- 不要求登录，不创建公开个人主页，不公开逐课进度。
- 新事件 `milestone_share` 只允许 `locale`、`channel`（`web-share` / `clipboard`）和 `outcome`（`succeeded` / `failed`）。
- 事件仍只进入本机开发者控制台，不发网络请求、不写 cookie / localStorage / IndexedDB，也不包含分享正文或 URL。
- 该表面已登记到 `src/lib/growth-surfaces.json`，受暗黑模式文案门禁和增长事件隐私门禁约束。

## 3. 明确拒绝的方案

### 3.1 排行榜

不做周榜、连胜榜、班级榜或收益率榜。原因：

- `docs/research.md` 中 Stock Academy 的排行榜是运营型班级产品的一部分，本项目的匿名、自定进度用户没有同等运营上下文。
- 连续学习一旦公开比较，断签会从“私人节奏”变成“公开失败”，与 R12.6 的温和恢复原则冲突。
- 交易教育中的“成绩”容易被误读为交易能力；排名还会奖励刷课或高风险练习，而不是理解。
- 一旦排行榜可分享，就需要防作弊、昵称审核、举报和申诉流程，v0.6 没有这些能力。

### 3.2 评论与论坛

不开放评论、私信、关注和好友。原因：

- 交易内容极易滑向荐股、带单、返佣和诈骗，必须有 7×24 审核与应急流程才安全。
- 需要新增举报、封禁、内容保留、未成年人保护和跨境数据治理设计，不能在“先上线再补”模式下降级处理。
- 论坛的成功依赖种子用户和长期运营；没有内容审核能力时，空论坛比没有论坛更伤害信任。

### 3.3 社交账号与可见性设置

不要求绑定手机号、券商账号或社交账号，也不引入“公开 / 好友 / 私密”三段可见性。分享动作是一次性的用户选择，不建立持久关系链。

- `e2e/smoke.spec.ts`：真实浏览器验证有进度可见、零进度静默。
- `npm run typecheck`、`npm run lint`、生产构建和 Lighthouse CI。

## 5. 重新评审条件

只有同时满足以下条件，才重新考虑评论或排行榜：

1. R13.23 的用户研究给出了直接需求证据，而不是竞品功能清单。
2. 有明确的内容审核负责人、举报 SLA、封禁与申诉流程。
3. 排行榜默认关闭、使用化名、绝不展示收益或交易结果，并允许完全退出。
4. 隐私影响评估通过，且不会把学习数据用于广告画像或付费诱导。
5. 有独立的 abuse、安全和运营预算，不把成本转嫁给匿名用户。
